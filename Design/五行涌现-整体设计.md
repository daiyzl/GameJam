# 五行涌现：整体设计草案 v0.3

本稿是下一阶段的建议设计。现有三个脚本完成了局部环境反应基础，尚未实现本文中的水流、燃烧传播、资源消耗、关卡目标或正式交互界面。本轮不修改脚本。

## 1. 核心体验与主题

类型：俯视角网格上的环境机关解谜。玩家在运行前布置有限的五行资源，启动后观察局部规则如何产生整体结果，失败后修改布置重试。

核心体验：玩家移动一份金或改变一处土，系统随后自行形成新的水路、林木分布和火势。玩家能够理解原因，也能够发现作者没有逐步脚本化的解法。

涌现来自三件事：局部规则相互作用；数量使反应速度和通行状态改变；反应结果继续改变下一步的环境。单独的克制曲线、随机事件和大量单位不作为主题的主要表达。

示例反馈：金持续切木 → 木变稀疏 → 水通过 → 下游木生长 → 下游通路变窄 → 水改道 → 原先的一处火被熄灭。

允许关卡拥有多个有效布局。不要检查玩家有没有使用预设解法，只检查最终世界状态是否满足目标。

## 2. 玩家操作

### 布置阶段

- 查看目标、初始元素数量和可修改区域。
- 使用有限的投放资源，在允许的格子放置元素、增加数量、撤回自己的投放。
- 初始地形和关卡元素不能随意删除；玩家撤回的只是自己的投放。
- 显示元素影响范围和当前格子的数量。
- 第一关只开放金；后续逐步开放土、水、火、木，不在第一关同时教授五种操作。

### 运行阶段

- 自动推进，可暂停、单步、正常速度和加速。
- 初版运行时不允许改布局，保持可重复观察的解谜体验。
- 每步显示切割、生长、水流和燃烧的来源。
- 可以随时选择重新布置，恢复初始世界并保留上次的投放方案。

### 结算阶段

- 满足目标立即获胜。
- 失败时停在现场，显示具体原因和发生步数。
- 一键返回布置阶段；无需重新摆放所有资源。

## 3. 地图与元素数据

初版地图约 8×6 至 12×8；设计完成后先用一张小地图验证规则。每格可同时存在五种数量，例如木和水可以共存。

每格保存：金量、木量、水量、火势、土量。额外的过程状态先只保存切割积累和反应余量。

各数量的含义不同：金是工具强度，木是植物/燃料量，水是可移动资源，火是火势，土是固定在格子上的生长基质。土还影响出水速度，表示蓄水能力。火势和影响强度不要求具有水量一样的守恒含义。

地图另有固定的不可修改岩壁、可用格和目标标记。岩壁用于限制地图边界和机关通路，避免玩家通过堆元素绕过整个谜题。

反应范围为自身格和上下左右四个相邻格。隔墙的格子不产生邻接影响；不读对角格；不读整张地图总量。邻域统计接口仍可只返回邻格数量，反应时再合并自身格。

水的移动必须读取具体相邻格的状态，不能只使用汇总量，因为汇总会丢失方向。

## 4. 五行规则

不要为每一对元素都增加一条效果。第一版只保留五条相克关系和水促木生长，让各元素承担明确职责。

| 关系 | 游戏中的作用 | 数量产生的差异 |
| --- | --- | --- |
| 金克木 | 金对影响范围内的木持续切割 | 木相对金越多，初期越慢；连续切割使效率逐渐提高；设置倍率上限 |
| 水、土生木 | 本格无火且已有木时，消耗土和水促进木生长 | 木∶土∶水增减比例为 1∶1∶2；土或水不足则停止增长 |
| 木克土 | 木生长时消耗本格土 | 直接使用上述资源转换，不再叠加一条独立的根系减土规则 |
| 土克水 | 土降低本格每步出水速度，表示蓄水能力 | 土多则水排出较慢；土少则排出较快；不直接删除水量 |
| 水克火 | 同格水消耗火势，水也相应消耗 | 小水量只能压低火势，大水量可熄灭；水通过移动到达火所在格 |
| 火克金 | 火势超过目标金的耐火阈值后，才削弱金量 | 弱火对金没有损伤积累；达标后火越强，金量下降越快 |
| 火生土 | 火实际烧掉的木转为本格土，表示灰烬回土 | 建议起点：烧掉 1 份木，恢复 1 份土；火量本身不凭空生成土 |

火同时需要一条用于形成连锁反应的燃料规则：水未能完全熄灭火时，剩余火势和本格木量共同决定燃烧速度。可以从“燃烧速度 ∝ 剩余火势 × 木量”开始，并设置每步燃烧上限、火势上限。木的实际消耗量决定火势增长和回土量。

火对木没有最低起效门槛。只要有效火势大于零、有木且未被扑灭，就持续积累燃烧量；弱火缓慢烧木，也可能逐渐变强。小数变化需要保留，不能直接取整丢失。无燃料时火势衰减直至熄灭，避免没有木仍无限扩张。

相邻格有火、本格有木且未被水浸湿时，可以点燃本格。新点燃的火下一步开始燃烧、影响金和向其他格传播，避免一格新火立即触发全图连锁。

木量同时决定水路的通透性：稀疏木使流量降低；达到密集阈值后堵住通路。具体阈值由关卡试玩确定。金切割使木跌破阈值，就会打开水路；水促进木生长，则可能重新关闭它。

### 金对木的连续作用

保留原型的方向：

```text
抵抗系数 = max(1, 木量 / 金影响量)
基础切割速度 = 金影响量 × 切割系数 / 抵抗系数
切割倍率 = min(上限, 1 + 连续作用时间 × 积累系数)
实际切割速度 = 基础切割速度 × 切割倍率
```

弱效果通过小数余量积累，不要直接取整为零。金影响消失时，初版清除连续切割积累。金量改变但仍大于零时，保留积累，便于理解。

金量表示区域工具强度，可同时影响多个邻接目标，这是明确的游戏规则。不会将同一份金搬到多个格子，也不会将环境快照当作可以各自消费的库存。

### 金与火的操作差异

金的主动作用仅为切木。它不主动改变土、水或火，但切木改变通路后，仍可能间接改变水流、生长和火传播。金适合精确打开通路、保留其他资源。

火作为激进选择，保留四条清楚的影响路径：烧木；烧掉的木回土；灭火需要消耗水；超过耐火阈值后损伤金。火不额外无条件增加土，也不额外叠加与灭火重复的蒸发扣水规则。

熔金规则建议用相对阈值：

```text
耐火阈值 = 目标金量 × 耐火系数
局部有效火势 ≤ 耐火阈值：金量不变，不积累隐性损伤
局部有效火势 > 耐火阈值：开始损伤金，超出越多损伤越快
```

局部有效火势读取灭火后的自身格与可影响邻格，不读取全地图火量。耐火系数是调参项；例如系数为 1、金量为 5 时，火势 5 及以下不损伤金，火势 6 才开始损伤。这只是规则示例，不是已验证的平衡数值。

本步燃烧新增的火势，下一步才参与熔金判断。附近木可能将安全的小火喂到危险阈值，因此界面需要同时提示当前火势、金的耐火阈值和火势增长趋势。

火的优势是借燃料扩大清场范围；代价包括扩散烧掉保护木、消耗有限灭火水、回土后增加再次生长的可能，以及扩大后损伤金。地图需提供可读的燃料连接、隔离带或水路，让玩家能够安排蔓延范围。

评估关卡时检查：火是否在清场范围和速度上有实际优势；有限水量、保护目标和回土后再生长是否使其有代价；金是否仍有安全、可控的有效解法。不强求两者在每关都等价。

### 木生长的资源预算

环境里的水可以用于提示生长机会；真正扣除的是木所在格的实际水和土。禁止多个格子分别根据同一份邻格资源生长并各自“消耗”它。

本格在这一模拟步开始时火量为零，才允许木生长。有火的格子不生长，即使火在本步被水熄灭，也从下一步才恢复生长。邻格火通过传播影响本格。

按木∶土∶水 = 1∶1∶2，实际生长量为：

```text
生长量 = min(本步生长额度, 本格土量, floor(本格水量 / 2), 木量上限 - 当前木量)
木 += 生长量
土 -= 生长量
水 -= 2 × 生长量
```

土为零或水不足 2 时，停止增加木。邻域中有水不会绕过本格资源约束。初版可从每步最多增长 1 份木开始，之后再调整生长速度函数；比例决定资源消耗，不自动决定速度。

木量为零的格子不自行长木，保持金切割和火清场的明确结果。需要重新长木的关卡，玩家必须保留少量木，或在布置阶段投放木。种子和自然扩散暂不加入。

### 土：基质、蓄水与灰烬回补

土固定在格子上。初版数量变化来自玩家初始投放、木生长消耗，以及木燃烧后的灰烬回补。

建议土只控制出水速度，不同时绑定地形高度，避免消耗一份土同时改变多个难以解释的物理参数：

```text
土造成的出水额度 = 基础出水额度 / (1 + 土量 × 阻滞系数)
```

水量差决定流向，土决定排水的快慢，木密度决定是否能通行。小流量需要累积或使用足够细的水量单位，不能因为取整而让所有厚土格永久不出水。

金切掉的木不回土；只有实际燃烧的木回土。这样清场方式不同，后续环境也不同：金可能留下土已耗尽的空地，火可能留下可再次生长、排水较慢的土。

回土量建议从 1∶1 开始；若以后调整，比例不大于 1，避免反复种植和燃烧凭空制造更多土。土耗尽不会直接判失败，只使本格不能继续生长。

## 5. 水流模型

采用离散水量转移，无需真实流体模拟。

- 水源是初始储水或有明确总量上限的供水装置。
- 根据固定的地形高度、本格水量、相邻格高度和水量，决定水面差。土量不改变固定地形高度。
- 水只朝水面更低、边界可通行的邻格移动；同高时不转移，方向对称时采用固定的分配规则。
- 木的密度改变边界通透性。密集木阻断；稀疏木限制最大每步流量。
- 土量限制本格出水额度；更多土让水排出较慢。出水仍需存在水面差和可通行边界。
- 同一格向多个邻格分配水时，总流出量不得超过本格在本轮生长和灭火结算后的剩余水量。
- 各格先计算流出预留，再统一应用流入与流出；必要时按比例缩减各出口流量，余数按固定方向顺序分配。
- 终点水槽接收并保存水，不再流出；收到的水从地图可移动水量中扣除。
- 一步中新流入的水不会再跨下一条边转移，确保水的传播速度可观察。

应满足水量账本：

```text
初始水量 + 已供给水量
= 地图剩余水 + 水槽收水 + 生长耗水 + 灭火耗水
```

第一张验证地图可以限制为一条有分支的水道，降低流量调参难度。若水流模型出现无法解释的来回摆动，优先减小每步流量并增加启动转移所需的水面差，不增加随机性。

## 6. 模拟顺序

建议每 0.5 秒推进一次逻辑；画面在逻辑步之间插值。时间是模拟时间，加速不会改变结果。

每步分三阶段，每个阶段全图计算后统一提交：

1. 检查步开始时的火量；无火且有木的格子按 1∶1∶2 消耗本格土和水，增加木。有火格跳过生长。
2. 先统一结算水灭火，形成剩余水量和有效火势快照；再计算金切木、火烧木、火影响金、火传播及灰烬回土。切割与燃烧争用木时，先预留切割量，燃烧只能消耗剩余木，回土只按实际燃烧量计算。
3. 使用反应后的木密度、土量、剩余水量，计算水流并统一提交。新流入的水下一步才能促木生长或灭火。

已经被水熄灭的火，在这一阶段不再燃烧或向邻格传播。新点燃的火下一步才开始作用。火势增长只依赖灭火后的有效火势和实际剩余燃料，不能先烧木增火再判断本步已有水是否足够。

前一阶段的结果可作为下一阶段的输入，但同一阶段内只读取快照。任何阶段都不能边改共享地图边让后面的格子读取修改后的结果。土的资源消耗与回补、火的燃料消耗都需要统一预算。

完成反应后检查失败与胜利。同一步守护目标被毁且水槽装满，按失败处理，避免结算歧义。

## 7. 目标和失败

第一关只有一个目标：在限定步数内，让终点水槽收够指定水量。

后续关卡加入一个保护条件：收水完成时，指定守护树仍存活。

示例参数可从 10 份目标水量、30 步时限开始。这些是调试起点，不代表已经验证过的关卡平衡。时限始终可见，按模拟步计数，暂停不计时。

失败条件：达到时限但未达成目标；保护关卡中守护树量降到零。元素用完、普通木消失、水暂时堵塞，都不直接判失败。初版不实现复杂的“已无解”自动检测，避免错误判断仍有机会完成的局面。

玩家可随时重试。失败面板显示“第几步、哪个目标、发生什么”，并保留现场供查看。

## 8. 关卡教学顺序

这些是机制验证目标，具体布局必须通过实际模拟检查可解性与多解性。

1. **切开通路**：金、木、水；学习金切木和木的通行阈值。
2. **留住通路**：加入水促木生长；过早放水会促进堵塞，玩家调整金的数量与位置。
3. **改变水路**：开放玩家投放土并加入两条分支；学习蓄水、分流，以及木生长耗土后出水变快。
4. **扑灭火势**：加入火与燃料传播；引水扑火，理解生长和灭火争用水。
5. **保住工具**：火会削弱金；清场与切割之间产生取舍，结合保护目标。

完整 Jam 版本先以 3 个小关卡为目标；若没有时间将火做好，优先保证金木水土系统完整可玩。土从第一关作为固定基质存在，玩家对土的投放在后续关卡开放。

## 9. 性能与实现预算

设格子数为 N，元素种类固定为 5。每格只读取最多四邻格，反应是 O(N)，水转移也只处理局部边，仍为 O(N)。不要使用每格遍历整张地图的 O(N²) 方法。

以 20×20 的地图估算，邻域汇总约为 `400×4×5 = 8000` 次数量读取/步。每秒两步约 16000 次；这只计算邻域汇总，实际还包括规则、水流和显示工作，并不是帧率实测。在小型网格上，这一规模适合作为原型起点，最终用实际地图做性能测量。

现有代码每步创建新的数组和大量 BaseElement 对象。正式接入时建议使用预分配的两份状态缓冲区并交换，降低垃圾回收；使用整数/结构体数组保存格子状态。

渲染避免每格每种元素都建立 GameObject。可用 Tilemap/Sprite 表示主要状态，选中格子才展开数字；调试 Gizmos、标签和每步完整日志在正常游玩时关闭。

小地图先全图扫描。活跃格队列、分区、多线程和 GPU 计算暂不加入；只有实际测量出现瓶颈才考虑。画面和逻辑频率分离，避免在每个渲染帧都运行完整模拟。

## 10. 信息呈现与背景

每格用基础地形、木覆盖、水填充高度和火势表现主要状态。金用明显的工具标记表示；五种数量可在选中时展示，避免整图充满数字。

暂停时选中格子，显示：自身五行数量、邻域数量、当前切割倍率、预计下一步的生长/损伤/流动。提示直接描述因果，如“邻格金量 5；木量较大，切割较慢”“本格有火，停止生长”“本格土耗尽，停止生长”“水不足 2，停止生长”。

背景只需解释行为与目标：一座五行机关园失衡，玩家用有限元素恢复水路并保护园中的树。暂不需要长剧情或角色系统。

## 11. 实施与验收

先验证金木水土的资源消耗与水路反馈，再增加火和灰烬回土，最后制作正式界面与关卡。

第一阶段的验收：

- 相同初始地图和投放布局，在正常速度、加速和单步下得到相同结果。
- 邻格金量能汇总，少量金在长时间作用后仍能切木。
- 切木确实改变水的通行；无火时已有木按 1∶1∶2 消耗土、水后生长；缺土或缺水则停止。
- 玩家能观察到“打开水路后，下游生长又改变水路”的反馈。
- 水量账本成立，数量不为负；多个出口不会复制水。
- 土量账本成立：初始土量 + 燃烧回土 = 剩余土量 + 生长耗土；切割和燃烧不会重复消耗同一份木。
- 弱火对木可以累积作用；阈值以下的火对金即使持续很久也不产生损伤；超过阈值才损伤金。
- 至少一张地图存在两种不同的有效布局，玩家能通过反馈理解失败并改善方案。

如果第一阶段缺少有趣的决策，先调整数量阈值、影响范围、地图和资源预算，再考虑新增机制。
